# Wisp

Нативный Windows-клиент для голосового общения, демонстрации экрана и чата. C# / .NET 8 / WPF, без Electron/WebView. Linux-сервер на Go/Pion пересылает Opus/H.264 без перекодирования; PostgreSQL хранит аккаунты, сообщества, профили, сообщения и медиа. SQLite остаётся локальным кэшем.

## Установка сервера

[Пошаговая инструкция для VPS](docs/SERVER.md). Нужен публичный IPv4, Ubuntu amd64 и доступные 8443/TCP + 50000/UDP. PostgreSQL доступен только локально через Unix socket. Сервер и клиент этой ветки используют протокол 2 и собственную регистрацию; данные прежнего внешнего сервиса не импортируются по выбранному владельцем варианту.

## Windows

Скачать `Wisp-win-x64` из успешного workflow **Windows build**, полностью выйти из старой версии через трей, распаковать архив и запустить Wisp.exe. При первом подключении вставить HTTPS URL сервера и SHA-256 сертификата из установщика, затем создать новый аккаунт. Параметры сохраняются; вход защищён Windows DPAPI. Смена сервера: `Wisp.exe --setup`.

Крестик сворачивает Wisp в трей и сохраняет разговор. Настройки и кэш разных серверов разделены; старые локальные данные не удаляются.

## Возможности

- Сообщества, текстовые и голосовые каналы; фиксированного ограничения пяти человек нет. Реальная вместимость зависит от CPU, RAM и сети VPS.
- Голос Opus 48 кГц/20 мс с локальным RNNoise, mute/deafen, аватары и индикация речи. Нажатие на другого участника голосового канала открывает локальную громкость 0–100% и профиль. Уровень сохраняется на этом ПК.
- Демонстрация приложения, монитора или всех мониторов, H.264 до 1080p/60, отдельный звук демонстрации. Просмотр во весь Wisp, mini или полный экран. Безрамочный захват зависит от разрешений Windows; предусмотрен совместимый GDI-путь.
- Чат с выделением текста, вложениями до 16 МиБ, голосовыми сообщениями, пользовательскими эмодзи и звуковой панелью сообщества.
- Профили с аватарами/GIF, баннерами, описанием, присутствием и определением некоторых игр.
- Тёмная/светлая темы, единый логотип, модальные формы в одном окне, виртуализированные списки, нативная прокрутка без анимационной очереди.
- Строка SFU показывает подключение и HTTPS RTT; нажатие открывает сведения о маршруте и шифровании.

WebRTC остаётся необходимым нативным транспортом клиент—SFU. Прямой mesh и клиентские Google STUN-серверы удалены: ICE-проверки выполняются с публичным SFU. TURN не устанавливается. При блокировке UDP голос может не подключиться.

## Разработка

```powershell
dotnet restore Wisp.sln
dotnet test tests/Wisp.Core.Tests -c Release
dotnet test tests/Wisp.Desktop.Tests -c Release
```

Сборка RNNoise и portable автоматизированы в Windows CI. Для сервера используются закреплённые `go.mod`/`go.sum`; CI проверяет реальные PostgreSQL-операции и шесть нативных клиентов.
