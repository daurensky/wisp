# Wisp

Нативное приложение для небольших сообществ под Windows: компоновка с серверами, каналами, чатом и участниками, Firebase для аккаунтов и данных, прямой WebRTC для голоса и экрана. C# / .NET 8 / WPF, без Electron и WebView.

Это первая **альфа-версия**, а не готовая замена Discord. Сборка и автоматические тесты не заменяют проверку микрофона, воспроизведения и захвата экрана на настоящих Windows-компьютерах. Список таких проверок — в [docs/TESTING.md](docs/TESTING.md).

## Собственный сервер голоса

В ветке `codex/sfu-server` добавлен экспериментальный SFU для VPS: один исходящий поток с каждого клиента, Opus/H.264 без перекодирования, до пяти человек в комнате. [Установка на Ubuntu и подключение клиентов](docs/SFU.md). Режим включается в настройках после установки сервера; прежний P2P сохраняется по умолчанию.

## Настройка Firebase

В новой сборке подключена конфигурация Firebase проекта `wisp-dd1ec`. Перед запуском владелец проекта должен опубликовать [правила Realtime Database](firebase/database.rules.json). [Пошаговая инструкция](docs/FIREBASE.md) описывает регистрацию по email, приглашения и ограничения текущего голоса. Старые локальные учётные записи автоматически не переносятся.

Крестик сворачивает Wisp в трей и сохраняет разговор; выход — через меню значка. Вход сохраняется с защитой Windows DPAPI. Кнопки микрофона, звука и демонстрации появляются после подключения голоса; выход из канала доступен и в состоянии ожидания.

## Возможности

- Чёрная тёмная и светлая темы, серверы-сообщества, текстовые и голосовые каналы.
- Единый нативный интерфейс WPF: собственная шапка, модальные формы внутри окна, векторные иконки, виртуализируемые списки и компактный режим. Конечные анимации учитывают настройки Windows; «Уменьшить анимации» доступно в профиле и настройках. [Отчёт UI-рефакторинга](docs/UI_REFACTOR.md).
- Firebase Authentication и Realtime Database для аккаунтов, профилей, сообществ, чата и присутствия; SQLite для локального кэша и медиа.
- Профиль: имя, описание, аватар и баннер; список подключённых участников и определение некоторых запущенных игр.
- Голосовые каналы до **5 человек**, мгновенное состояние «Соединение», аватары участников, значки mute/deafen и зелёное кольцо речи. Отключение микрофона и режима прослушивания вместе с микрофоном.
- Локальное шумоподавление микрофона RNNoise 0.2, включено по умолчанию. Переключатель «Профиль и настройки → Звук · устройства → Шумоподавление» сохраняется на этом ПК и работает сразу. На звук демонстрации и входящий голос не влияет. При недоступной библиотеке голос продолжается без обработки с одним уведомлением.
- WebRTC mesh с настраиваемыми STUN-серверами (по умолчанию Google), без TURN по решению владельца. Opus через отдельную дорожку SRTP, моно 48 кГц, пакеты по 20 мс, целевой битрейт 32 кбит/с; FEC/PLC при потерях, адаптивный буфер 40–80 мс и WASAPI Communications. Микрофон и выход голоса выбираются в настройках и меняются без выхода из канала. Нативный libopus заменяет управляемый кодек, повреждённые пакеты отбрасываются без звукового сигнала.
- Демонстрация выбранного окна приложения или выбранного монитора. В списке источников учитываются несколько мониторов. Захват Windows.Graphics.Capture с курсором и резервом GDI. Нативный H.264 через Windows Media Foundation: до 1920×1080 и 60 кадров/с. Выбор 720p/1080p, 15/30/60 FPS и 2/4/6/8 Мбит/с на зрителя; по умолчанию 1080p/30 и 4 Мбит/с. Битрейт умножается на число зрителей; при длительных потерях общая кодировка снижает битрейт/FPS. Свёрнутое окно ставит показ на паузу до разворачивания. Реальная частота зависит от компьютера, старые кадры не накапливаются.
- Выделение и копирование текста сообщений; GIF в списке участников и сообщениях играют при наведении, в голосовом канале — при речи, GIF-баннер — при открытом профиле.
- Текстовый чат с отправкой по Enter (Shift+Enter — новая строка), предпросмотр вложений, голосовые WAV с паузой и перемоткой, пользовательские эмодзи внутри текста и звуковая панель сообщества.
- Звуковые сигналы подключения, отключения, переключения микрофона, прослушивания и демонстрации.

Клик по названию голосового канала подключает голос, кнопка «Чат» рядом открывает его переписку. Профили и настройки открываются поверх содержимого одного окна. Просмотр демонстрации занимает клиентскую область Wisp; ↘ уменьшает её в правый нижний угол и возвращает чат, ↖ разворачивает обратно. ⛶ или двойной щелчок включает полноэкранный режим текущего монитора; Escape выходит из него. «Уведомления» содержит предупреждения и ошибки, до 100 разных записей; повторы объединяются со счётчиком, звуковой сигнал ошибки ограничен одним разом в 15 секунд. Полосы прокрутки узкие, следуют теме и скрываются после прокрутки. Новые профили используют круглую аватарку Wisp (Io) из Dota 2; [источники и лицензии](docs/licenses/ASSETS.md).

При первом запуске используется тёмная тема с чёрным фоном, включая окно входа. Переключатель ◐ меняет тему всех окон; выбранная тема сохраняется для следующих запусков.

## Запуск и сборка

Нужна Windows 10 build 19041 (2004) или новее / Windows 11. Для сборки установите [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0); отдельная установка Visual Studio не обязательна.

```powershell
git clone --branch codex/hardening https://github.com/daurensky/wisp.git
cd wisp
dotnet run --project src/Wisp.Desktop/Wisp.Desktop.csproj
```

Чтобы получить ZIP с приложением и включённой средой .NET:

```powershell
pwsh -File ./build.ps1
```

Результат — `artifacts/Wisp-win-x64.zip`. Распакуйте **всю** папку и запустите `Wisp.exe`. Эта версия не создаёт установщик и не подписывает исполняемые файлы. Альтернативно после успешного workflow **Windows build** ZIP можно скачать из его раздела **Artifacts** на GitHub. Наличие workflow не означает, что конкретная сборка уже прошла.

## Подключение друзей

Для Firebase используйте [новую инструкцию](docs/FIREBASE.md). Ниже описан прежний режим прямой связи без Firebase.

1. Создайте локальный аккаунт и сообщество. Владелец открывает сессию на своём компьютере.
2. Разрешите приложению входящие подключения в брандмауэре Windows для нужной сети. Порт по умолчанию — **TCP 45832**.
3. Отправьте друзьям полное приглашение `wisp://…`, содержащее адрес, отпечаток сертификата и секрет сессии. Ссылка даёт доступ к сессии — не публикуйте её для посторонних.
4. Друг входит в свой локальный аккаунт и подключается по приглашению. Для разговора выберите один голосовой канал; шестой участник в занятый канал не допускается.

Каналы создаёт владелец сообщества. В этой версии для изменения списка каналов нужно остановить сессию и открыть её заново; приглашение при этом меняется. Голосовое сообщение записывается вне звонка. Звуковая панель передаёт звук участникам текущего голосового канала; вне звонка звук можно прослушать локально.

В режиме Firebase голос использует WebRTC mesh и настраиваемые STUN-серверы без ретрансляции — [инструкция и ограничения](docs/FIREBASE.md). Ниже описан только прежний режим без Firebase.

В режиме без Firebase все данные передаются по TLS непосредственно между компьютерами участников. **Топология — звезда:** компьютер владельца сессии принимает подключения и пересылает данные остальным. Это участник разговора, а не отдельный постоянно работающий сервер; полный mesh P2P пока не реализован. Владелец должен оставаться онлайн. При его выходе сессия заканчивается, автоматической передачи роли хоста нет.

В одной локальной сети обычно достаточно локального IP. Для интернета в режиме без Firebase нужен доступный адрес владельца и перенаправление TCP-порта на роутере либо общая VPN-сеть с прямой доступностью. При CGNAT, блокировках входящего трафика и без такой доступности соединение не установится. В режиме без Firebase STUN/TURN, облачного сигналинга и обхода NAT нет. В приглашении должен быть адрес, доступный именно другим участникам, а не только компьютеру владельца.

## Данные и ограничения

- Данные находятся в `%LOCALAPPDATA%\Wisp`: `wisp.db`, каталог `media`, сертификаты идентичностей и доверенные отпечатки. Пароли прежних локальных аккаунтов хешируются PBKDF2-SHA256 со случайной солью; аккаунты Firebase обслуживает Firebase Authentication. Сама SQLite и локальные медиа не зашифрованы.
- В режиме без конфигурации Firebase регистрация действует **только на этом ПК**. Общего реестра пользователей, регистрации по почте, восстановления пароля и автоматического переноса аккаунта нет. Одинаковые имена на разных ПК возможны; сетевую идентичность задаёт сертификат.
- В режиме без Firebase хост проверяется по отпечатку из приглашения, сертификаты участников закрепляются при первом подключении. TLS шифрует участки связи до хоста; хост может читать пересылаемые данные. Сквозного шифрования между участниками поверх хоста пока нет.
- Firebase хранит историю чата; при открытии канала загружаются последние 100 сообщений. SQLite хранит локальный кэш. Вложения и голосовые сообщения загружаются в закрытый для посторонних узел сообщества в Realtime Database частями по 512 КиБ, затем кэшируются на устройстве получателя; вход в голосовой канал не нужен. Эмодзи сохраняются в сообществе с доступом только для участников; максимум 32 разных эмодзи в сообщении. Дополнительно медиа передаются напрямую подключённым пирам. Аватары до 4 МиБ (один текущий слот, чтение для вошедших пользователей) синхронизируются через Firebase и кэшируются по хешу; GIF проигрываются бесконечно. Баннеры передаются участникам активной сессии; локальные пути на другие компьютеры не отправляются.
- Обычные вложения ограничены 16 МиБ, голосовые файлы — 5 МиБ, загрузка эмодзи — 256 КиБ, звуковой панели — 2 МиБ. Запись голосового сообщения — до 60 секунд. Вложения сохраняются через диалог выбора файла и не запускаются автоматически.
- На Windows 11 / Windows Server 2022 (build 20348+) демонстрация передаёт стереозвук выбранного приложения с дочерними процессами либо системный звук при выборе монитора. Wisp исключается из системного захвата, чтобы речь участников не возвращалась эхом. Звук идёт отдельной дорожкой SRTP, mute микрофона его не выключает. Кнопка звука в плеере отключает демонстрацию только для зрителя. На Windows 10 видео работает, звук захвата с исключением Wisp недоступен. Защищённый контент может давать чёрный кадр. Резервный GDI дополнительно ограничен для GPU-окон; сворачивание повторяет последний кадр с пометкой паузы. Можно выбрать отдельный монитор, окно или объединённый рабочий стол из всех мониторов; размер итогового кадра ограничен 1920×1080. Нативное кодирование использует встроенные MFT Windows; использование аппаратного кодировщика не гарантируется. 1080p/60 потребляет заметно больше CPU и сети, чем 720p/30.
- RNNoise работает перед кодировщиком микрофона; системные эффекты Communications дополнительно зависят от драйвера. Отдельные AEC (эхоподавление) и АРУ пока не добавлены; для отсутствия акустического эха используйте гарнитуру. RNNoise не гарантирует удаления чужих голосов и может менять тембр речи. Качество и задержка требуют проверки на реальных устройствах. Сборка нативной библиотеки и происхождение исходников: [native/rnnoise](native/rnnoise/README.md).
- Определение игр использует небольшой список имён процессов; это не интеграция с каталогами игр или платформами.

Подробности реализации — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), сетевого протокола — [docs/P2P.md](docs/P2P.md).

Все участники должны обновиться вместе: SRTP-дорожки голоса/звука/видео и управляющие каналы v2 несовместимы с прежним SCTP-медиапротоколом. Эта ветка дополнительно требует новых правил Firebase с Attempt/CreatedAt и rtcCandidates; порядок выпуска указан ниже.

Ветка `codex/hardening` изменяет правила доступа и требует согласованного обновления всех клиентов. Старые облачные файлы остаются только у автора, локальные копии получателей сохраняются. Перед запуском новой версии выполните [порядок выпуска](docs/FIREBASE.md#порядок-выпуска-правил-и-клиента-hardening); агент правила не публикует.

Прямые пары восстанавливаются с ограниченными повторами 2/5/15/30 с; сигналинг использует серверное время, trickle ICE и один поток SSE на голосовой клиент. Между произвольными NAT связь без TURN не гарантируется. Результаты проверок, исключённые по согласованию пункты и ручные сценарии — [HARDENING.md](docs/HARDENING.md) и [TESTING.md](docs/TESTING.md).
