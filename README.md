# Wisp

Нативное приложение для небольших сообществ под Windows: компоновка с серверами, каналами, чатом и участниками, локальные аккаунты и связь без центрального сервиса. C# / .NET 8 / WPF, без Electron и WebView.

Это первая **альфа-версия**, а не готовая замена Discord. Сборка и автоматические тесты не заменяют проверку микрофона, воспроизведения и захвата экрана на настоящих Windows-компьютерах. Список таких проверок — в [docs/TESTING.md](docs/TESTING.md).

## Настройка Firebase

В новой сборке подключена конфигурация Firebase проекта `wisp-dd1ec`. Перед запуском владелец проекта должен опубликовать [правила Realtime Database](firebase/database.rules.json). [Пошаговая инструкция](docs/FIREBASE.md) описывает регистрацию по email, приглашения и ограничения текущего голоса. Старые локальные учётные записи автоматически не переносятся.

Крестик сворачивает Wisp в трей и сохраняет разговор; выход — через меню значка. Вход сохраняется с защитой Windows DPAPI. Кнопки микрофона, звука и демонстрации появляются после подключения голоса; выход из канала доступен и в состоянии ожидания.

## Возможности

- Чёрная тёмная и светлая темы, серверы-сообщества, текстовые и голосовые каналы.
- Firebase Authentication и Realtime Database для аккаунтов, профилей, сообществ, чата и присутствия; SQLite для локального кэша и медиа.
- Профиль: имя, описание, аватар и баннер; список подключённых участников и определение некоторых запущенных игр.
- Голосовые каналы до **5 человек**, отключение микрофона и режима прослушивания вместе с микрофоном.
- Opus, моно 48 кГц, пакеты по 20 мс, целевой битрейт 32 кбит/с; ограниченные буферы воспроизведения.
- Демонстрация выбранного окна приложения или выбранного монитора. В списке источников учитываются несколько мониторов. JPEG до 1280×720, до 5 кадров/с для умеренной нагрузки.
- Текстовый чат, вложения, голосовые сообщения WAV, пользовательские эмодзи как изображения в сообщениях и звуковая панель сообщества.
- Звуковые сигналы подключения, отключения, переключения микрофона, прослушивания и демонстрации.

При первом запуске используется тёмная тема с чёрным фоном, включая окно входа. Переключатель ◐ меняет тему всех окон; выбранная тема сохраняется для следующих запусков.

## Запуск и сборка

Нужна Windows 10/11. Для сборки установите [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0); отдельная установка Visual Studio не обязательна.

```powershell
git clone --branch codex/native-windows-p2p https://github.com/daurensky/wisp.git
cd wisp
dotnet run --project src/Wisp.Desktop/Wisp.Desktop.csproj
```

Чтобы получить ZIP с приложением и включённой средой .NET:

```powershell
pwsh -File ./build.ps1
```

Результат — `artifacts/Wisp-win-x64.zip`. Распакуйте **всю** папку и запустите `Wisp.exe`. Эта версия не создаёт установщик и не подписывает исполняемые файлы. Альтернативно после успешного workflow **Windows build** ZIP можно скачать из его раздела **Artifacts** на GitHub. Наличие workflow не означает, что конкретная сборка уже прошла.

## Подключение друзей

Для Firebase используйте [новую инструкцию](docs/FIREBASE.md). Ниже описан прежний режим прямой связи без Firebase.

1. Создайте локальный аккаунт и сообщество. Владелец открывает сессию на своём компьютере.
2. Разрешите приложению входящие подключения в брандмауэре Windows для нужной сети. Порт по умолчанию — **TCP 45832**.
3. Отправьте друзьям полное приглашение `wisp://…`, содержащее адрес, отпечаток сертификата и секрет сессии. Ссылка даёт доступ к сессии — не публикуйте её для посторонних.
4. Друг входит в свой локальный аккаунт и подключается по приглашению. Для разговора выберите один голосовой канал; шестой участник в занятый канал не допускается.

Каналы создаёт владелец сообщества. В этой версии для изменения списка каналов нужно остановить сессию и открыть её заново; приглашение при этом меняется. Голосовое сообщение записывается вне звонка. Звуковая панель передаёт звук участникам текущего голосового канала; вне звонка звук можно прослушать локально.

Все данные передаются по TLS непосредственно между компьютерами участников. **Топология — звезда:** компьютер владельца сессии принимает подключения и пересылает данные остальным. Это участник разговора, а не отдельный постоянно работающий сервер; полный mesh P2P пока не реализован. Владелец должен оставаться онлайн. При его выходе сессия заканчивается, автоматической передачи роли хоста нет.

В одной локальной сети обычно достаточно локального IP. Для интернета нужен доступный адрес владельца и перенаправление TCP-порта на роутере либо общая VPN-сеть с прямой доступностью. При CGNAT, блокировках входящего трафика и без такой доступности соединение не установится. STUN/TURN, облачного сигналинга и обхода NAT в этой версии нет. В приглашении должен быть адрес, доступный именно другим участникам, а не только компьютеру владельца.

## Данные и ограничения

- Данные находятся в `%LOCALAPPDATA%\Wisp`: `wisp.db`, каталог `media`, сертификаты идентичностей и доверенные отпечатки. Пароли хешируются PBKDF2-SHA256 со случайной солью. Сама SQLite и локальные медиа не зашифрованы.
- В режиме без конфигурации Firebase регистрация действует **только на этом ПК**. Общего реестра пользователей, регистрации по почте, восстановления пароля и автоматического переноса аккаунта нет. Одинаковые имена на разных ПК возможны; сетевую идентичность задаёт сертификат.
- Хост проверяется по отпечатку из приглашения, сертификаты участников закрепляются при первом подключении. TLS шифрует участки связи до хоста; хост может читать пересылаемые данные. Сквозного шифрования между участниками поверх хоста пока нет.
- История чата хранится локально; доставки сообщений отсутствующим участникам и полной синхронизации старой истории нет. Аватар и баннер до 4 МиБ каждый передаются участникам активной сессии; локальные пути на другие компьютеры не отправляются.
- Обычные вложения ограничены 16 МиБ, голосовые файлы — 5 МиБ, загрузка эмодзи — 256 КиБ, звуковой панели — 2 МиБ. Запись голосового сообщения — до 60 секунд. Вложения сохраняются через диалог выбора файла и не запускаются автоматически.
- Демонстрация не передаёт системный звук или звук приложения. Захват GDI может не отображать защищённый контент, свёрнутые окна и некоторые аппаратно ускоренные приложения. Можно выбрать отдельный монитор, окно или объединённый рабочий стол из всех мониторов; размер итогового кадра ограничен 1280×720.
- Акустического эхоподавления и развитого шумоподавления пока нет; используйте гарнитуру. Качество и задержка зависят от устройств и сети. Заявлений о конкретной загрузке CPU/RAM без замеров нет.
- Определение игр использует небольшой список имён процессов; это не интеграция с каталогами игр или платформами.

Подробности реализации — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), сетевого протокола — [docs/P2P.md](docs/P2P.md).
