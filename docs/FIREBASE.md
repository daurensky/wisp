# Firebase и соединения через интернет

В сборку включена публичная клиентская конфигурация проекта `wisp-dd1ec`. Веб-SDK не нужен: нативное приложение использует Firebase Authentication REST и Realtime Database REST по HTTPS. Пароли в SQLite не копируются; Firebase refresh token хранится через Windows DPAPI для текущего пользователя ОС. SQLite остаётся кэшем истории и медиа. Старые локальные аккаунты не превращаются автоматически в Firebase-аккаунты: один раз зарегистрируйтесь с email в обновлённом приложении.

## Настройка владельцем проекта

1. В Firebase Console → Authentication → Sign-in method включите Email/Password. Проверка подключения к этому проекту уже подтвердила доступность регистрации; временный проверочный аккаунт удалён.
2. Откройте Realtime Database → Rules. Вставьте **весь** файл [database.rules.json](../firebase/database.rules.json) и нажмите Publish. Не включайте публичное чтение/запись базы. Клиентская конфигурация не даёт административных прав, поэтому приложение не может опубликовать правила за владельца.
3. Запустите новую сборку. Зарегистрируйтесь с email и именем. Следующие запуски восстанавливают Firebase-сессию. «Выйти из аккаунта» находится в меню значка трея.
4. Создайте сообщество и отправьте другу приглашение `wisp-cloud:…` через кнопку «Пригласить». Он регистрируется в том же проекте и вставляет приглашение кнопкой ↗. Код сообщества служит приглашением: доступ получает тот, кому известен непредсказуемый идентификатор; отдельных ролей и отзыва приглашений пока нет.

Профили, состав сообществ, каналы, последние 100 сообщений выбранного канала и присутствие синхронизируются через Firebase. Обновление присутствия — примерно каждые 5 секунд; при аварийном выходе отметка исчезает у клиентов через 45 секунд. Кнопка выхода из голосового канала не закрывает сообщество. Владелец автоматически открывает текущую P2P-сессию при входе в голосовой канал. Его endpoint публикуется только для участников сообщества.

## Что пока не решено Firebase

**Голос по-прежнему использует прежний TLS/TCP-транспорт через участника-владельца.** Firebase обеспечивает вход, чат и видимость каналов через исходящий HTTPS без портов/VPN, но не превращает TCP-голос в WebRTC. Состояние «В канале · голос ещё не подключён» означает ожидание соединения, а не работающий разговор. Лимит 5 подключённых к голосу участников проверяет хост; облачный список ожидания пока не имеет транзакционного распределения мест.

Чтобы голос работал без настройки роутера, нужен следующий этап: WebRTC, обмен SDP/ICE через защищённые записи Firebase, STUN и TURN с краткоживущими учётными данными. TURN обязателен как резерв для CGNAT/строгих сетей; его трафик оплачивается отдельно от Firebase. Не встраивайте постоянный секрет TURN в клиент. Полный разговор и демонстрация без доступного хоста пока не реализованы.

Медиа и изображения профиля пока передаются прежним P2P-способом и сохраняются локально. Cloud Storage не подключён; Firebase Spark не следует считать бесплатным хостингом медиа. По действующим условиям Storage требует Blaze. Не включайте биллинг без собственного решения о расходах.

Официальные условия: [Realtime Database](https://firebase.google.com/docs/database/usage/limits), [оплата базы](https://firebase.google.com/docs/database/usage/billing), [требования Storage](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024).

## Закрытие приложения

Крестик скрывает окно и демонстрации в трей; голосовая сессия и захват продолжаются. Двойной щелчок по значку открывает окно. Для завершения выберите «Закрыть Wisp» в меню трея. Перед заменой файлов сборки завершайте приложение этим пунктом.
