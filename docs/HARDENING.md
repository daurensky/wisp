# Wisp hardening: выполнение по фазам

Рабочая ветка: `codex/hardening`, база `codex/native-windows-p2p` на коммите `5f292cb`.
Изменения в исходную ветку и `main` не отправляются. Правила в рабочую Firebase-базу агент не публикует; производственные данные не изменяет и не удаляет.

## Согласованные решения

- Старые `profiles/*/Files` остаются в базе и читаются только автором. Новые вложения хранятся в сообществе; локальные копии старых файлов сохраняются.
- Аватары доступны авторизованным пользователям. Пользовательские эмодзи доступны только участникам соответствующего сообщества.
- По ответу владельца перед фазой 2 TURN не нужен. TURN-сервер, API временных учётных данных и relay-тест исключены из объёма работ. Настройка STUN и восстановление прямой связи остаются; ограничения NAT документируются.
- Приглашения-токены с отзывом не реализуются без отдельного согласования.

## Фаза 0: базовая линия

- `dotnet restore Wisp.sln`: успешно, Linux.
- `dotnet test tests/Wisp.Core.Tests -c Release --no-restore`: 30/30, Linux.
- `dotnet build Wisp.sln -c Release --no-restore`: успешно, 0 предупреждений / 0 ошибок, Linux (cross-build Windows-проектов).
- Подготовлен изолированный Realtime Database Emulator для проекта `demo-wisp-hardening`. Он не подключается к производственной базе.
- 4/4 базовых теста правил прошли в локальном эмуляторе. Тест P0-1 подтвердил, что посторонний вошедший пользователь читает голосовое вложение; после фазы 1 ожидание заменяется на запрет. Проверены также анонимное чтение, права SDP и пять фиксированных мест.
- Для локального запуска исправлено соблюдение существующего `NO_PROXY` только для loopback в установленных (не коммитящихся) копиях Firebase CLI/SDK: их версии принудительно использовали внешний прокси даже для `127.0.0.1`. Для остальных адресов унаследованный прокси сохранён. На CI без прокси используются неизменённые npm-пакеты.
- Исходники SIPSorcery читаются с коммита NuGet-пакета `08c2ed0ad72c423ca06950dee2e842488a219884`, а не из `main`.

WPF, Media Foundation, WASAPI и Windows.Graphics.Capture в Linux не выполнялись. Новые изменения этой ветки пока **не проверены на Windows**. Прежняя CI исходной ветки не считается проверкой новых изменений.

## Фаза 1: приватность файлов и ограничение структуры

Новые вложения/голосовые переведены в узлы сообщества, старые оригиналы закрыты для всех, кроме автора. Новые эмодзи доступны участникам сообщества. Аватары используют один текущий слот, доступны вошедшим пользователям; старые публичные эмодзи закрыты. Правила ограничивают размер частей, число частей (32), полноту и неизменяемость файла, поля и типы профилей/сообщений/SDP. Метаданные файла содержат ровно четыре поля.

Максимум 32 разных эмодзи в новом сообщении проверяется фиксированными серверными слотами; прежняя карта токенов сохраняется только для чтения старой истории. Базовая тестовая утечка теперь проверяется как отказ. В эмуляторе прошли 13/13 тестов, включая реальный REST conditional PUT/412, запрет чтения через родителя, превышение размеров и лишние поля.

Порядок выпуска: сначала подготовить/раздать новый клиент и завершить старые процессы, затем владелец публикует строгие правила, затем запускаются новые клиенты. Автоматической миграции, удаления производственных данных и публикации правил нет. Детали — FIREBASE.md. Объектные ограничения не заменяют глобальный контроль квоты или защиту открытой регистрации.

После фазы 1: `dotnet build Wisp.sln -c Release --no-restore` — успешно, 0 предупреждений / 0 ошибок; `dotnet test tests/Wisp.Core.Tests -c Release --no-restore` — 31/31. 13-й тест эмулятора подтверждает, что обновление профиля не удаляет старые файлы и скалярные поля. Новые изменения пока **не проверены на Windows**.

## Фаза 2: настройка ICE без TURN

По явному решению владельца добавлены только провайдер STUN, проверяемый файл настроек и диалог «Сеть · STUN». Одна запись `RTCIceServer.urls` содержит одну строку URL; тесты пиров получают пустой список. Уведомления показывают тип номинированной пары без адресов. API сверены с SIPSorcery 10.0.17 по коммиту пакета. Сборка: 0 предупреждений/ошибок; core: 39/39. Новый диалог **не проверен на Windows**.

TURN-учётные данные, coturn/API и проверка `relay` намеренно не реализованы и не разворачиваются. Ограничения прямой связности сохраняются.
