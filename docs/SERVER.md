# Wisp server v2: PostgreSQL + SFU

Целевая машина: Ubuntu26.04 amd64, 89.126.195.20 (Астана), 1vCPU/2GB/25GB. Служба пересылает медиа без перекодирования и обслуживает вход, профили, чат, файлы, приглашения и сигналинг. PostgreSQL работает локально. Логического лимита пяти человек нет; аппаратная ёмкость зависит от CPU/сети и числа демонстраций.

## Установка/обновление

В своём SSH-сеансе root:

```bash
apt-get update
apt-get install -y git
git clone --branch codex/postgres-backend --single-branch https://github.com/daurensky/wisp.git /opt/wisp-server-v2-src
cd /opt/wisp-server-v2-src
bash server/wisp-sfu/deploy/install.sh 89.126.195.20
```

Каталог должен быть новым. Для повторного запуска из того же checkout достаточно `git pull --ff-only` и команды install.sh. Скрипт можно прочитать перед запуском.

Установщик собирает закреплённую версию Go-модуля, проверяет SHA256 SDK, устанавливает PostgreSQL, создаёт локальную роль `wisp-sfu` и БД `wisp`, обновляет `/etc/wisp-sfu/server.json`, перезапускает существующую службу `wisp-sfu`. Unix peer authentication сопоставляет системного пользователя службы с ролью PostgreSQL: пароль БД не нужен. Административных ролей приложению не выдаётся.

Существующие TLS-сертификат и приватный ключ сохраняются, поэтому прежний SHA-256 остаётся действительным. Конфигурация предыдущего backend сохраняется в root-only `.before-postgres`. Скрипт не удаляет внешние проекты, старые локальные кэши или существующие базы PostgreSQL. При первичном переходе с прежнего сервиса/протокола1 старые аккаунты не импортировались. **При обновлении уже установленного PostgreSQL backend v2 регистрация заново не требуется:** аккаунты, сообщения, файлы, сертификат и конфигурация сохраняются. Новое поле роли участника добавляется через ADD COLUMN IF NOT EXISTS.

При первом создании config получит:

```json
{
  "backendVersion": 2,
  "listen": ":8443",
  "publicIp": "89.126.195.20",
  "udpPort": 50000,
  "certificate": "/etc/wisp-sfu/server.crt",
  "privateKey": "/etc/wisp-sfu/server.key",
  "databaseDsn": "host=/var/run/postgresql user=wisp-sfu dbname=wisp sslmode=disable",
  "registrationOpen": true,
  "maxSessions": 0
}
```

`maxSessions:0` снимает программный общий лимит. Это не обещание неограниченной производительности. `registrationOpen:false` закрывает новую регистрацию после создания нужных аккаунтов; вход уже зарегистрированных продолжит работать. После изменения config перезапустить службу.

## Сеть и клиент

| Назначение | Доступ |
|---|---|
| HTTPS API/WSS/health | 8443/TCP публично |
| WebRTC ICE + DTLS/SRTP/SCTP | 50000/UDP публично |
| PostgreSQL | только локальный Unix socket; не открывать5432 наружу |

Разрешить эти два публичных порта на VPS и в панели провайдера. Установщик не меняет SSH/UFW. Не включать firewall вслепую без разрешения своего SSH-порта.

После успешного старта выводятся **публичные** URL и SHA-256. В новом Windows-клиенте ввести HTTPS адрес и этот отпечаток, при первом использовании создать аккаунт или войти в существующий аккаунт v2. Старый клиент с протоколом1 несовместим: обновить всех участников. Строка SFU показывает HTTPS RTT и маршрут. Перенастройка адреса — `Wisp.exe --setup`.

WebRTC необходим клиенту для нативной передачи и воспроизведения медиа. Отдельные Google STUN-серверы не используются: клиент получает публичный адрес SFU в SDP, а STUN-проверки ICE выполняются с ним. Клиентский mesh удалён. TURN не устанавливается; сеть, блокирующая UDP, может препятствовать голосовому подключению. Медиа шифруются на участке клиент—SFU; сервер имеет доступ к сжатым пакетам в RAM.

## Контроль и сохранность данных

```bash
systemctl --no-pager --full status wisp-sfu
journalctl -u wisp-sfu -n 60 --no-pager
runuser -u postgres -- psql -d wisp -c '\dt'
free -h
```

Служба использует GOMAXPROCS1, целевой Go heap384MiB, MemoryMax768M; PostgreSQL живёт отдельно. Пул приложения ограничен четырьмя соединениями. Задачи хеширования паролей и HTTP-обработки ограничены по одновременности, но это не лимит участников канала. Несколько видеопотоков повышают CPU и исходящий трафик. Один поток8Мбит/с для пяти зрителей означает около18GB/час исходящего видео без накладных расходов.

Аккаунты и метаданные/медиа хранятся в PostgreSQL. Резервная копия (содержит личные данные, хранить закрыто):

```bash
umask 077
runuser -u postgres -- pg_dump -Fc wisp > /root/wisp-backup.dump
```

Отдельно сохранять конфигурацию и TLS-ключ в закрытом хранилище. Для отката бинарника не удалять БД. Автоматический переход к старому внешнему backend не выполняется. Не публиковать дампы, пароли или `server.key`; публичный SHA-256 можно передавать участникам.

## Управление сообществами

Контекстное меню значка сервера открывает настройки. Владелец может назначать и снимать администраторов; владелец/администратор меняют название, значок, каналы, эмодзи и звуки. Администратор может исключать обычных участников, владелец — также администраторов; владельца исключить нельзя. Права проверяются в PostgreSQL-транзакции управления. Исключённый участник теряет доступ к API и активному SFU-сеансу. Банов в текущей модели нет; новое действительное приглашение позволяет вступить снова.

Обновить существующий checkout:

```bash
cd /opt/wisp-server-v2-src
git pull --ff-only
bash server/wisp-sfu/deploy/install.sh 89.126.195.20
```

Новые клиенты используют совместимые дополнительные поля протокола2 для событий зрителей. Для управления сервером и новых звуков просмотра обновите сервер и клиенты; сбрасывать базу или сертификат не нужно.

Нативные настройки/редактор изображений: новые coverFrame и gain поля совместимы с существующими документами v2. GET управления, создание/переименование/удаление каналов и загрузка новых эмодзи проверяют owner/admin. Каждый участник отправляет уже загруженные эмодзи; клиент не пытается загрузить их повторно. Удаление голосового канала закрывает его сеансы, остальные каналы не затрагиваются. Подробности и новые проверки: [NATIVE_EXPANSION.md](NATIVE_EXPANSION.md).
